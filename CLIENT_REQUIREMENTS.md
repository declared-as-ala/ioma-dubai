## Business Decisions Needed From Client

- Which payment gateway to integrate for UAE (Stripe, Checkout.com, PayTabs, Network International, or other) — affects `PaymentProvider` adapter choice. The adapter interface and full checkout/order/webhook-idempotency flow are built and live-verified end to end (Sprint 4) against a `MockPaymentProvider`; a real gateway is a new class behind the same `PAYMENT_PROVIDER` DI token, not a flow rebuild.
- Which AI skin-analysis vendor (or in-house model) to integrate — affects the `AIProvider` adapter choice (`apps/api/src/modules/ai-analysis/providers/ai-provider.interface.ts`). The full consent → upload → async BullMQ pipeline → results flow is built and live-verified end to end (Sprint 6) against a `MockAIProvider` (deterministic, hash-derived indicator scores, `isSimulated: true` surfaced throughout the UI); a real vendor is a new provider class behind the same `AI_PROVIDER` DI token, not a flow rebuild.
- Whether Google Maps/Mapbox is preferred over the default keyless OSM/Leaflet map provider (brand/UX preference, not a hard requirement).
- Final domain name(s) and hosting target for production deployment.
- Confirmation of the "professional" role taxonomy against real-world partner types the business actually onboards (spa/clinic/institute/hotel/retail/diagnostic-center/distributor list is derived from the brief — confirm before Sprint 8 locks it in).
- Which transactional-email provider to use (affects `EmailProvider` adapter choice, still undecided — see `ENVIRONMENT.md`). Sprint 5's account module deliberately does not ship an email-based "forgot password" flow yet: `packages/validation/src/auth.ts` already has `forgotPasswordSchema`/`resetPasswordSchema` written ahead of time, but there's no backend endpoint and no way to actually deliver a reset email without this decision. "Change password while signed in" (`PATCH /account/password`, real and live-tested) covers the rest of Sprint 5's password/security requirement in the meantime.

## How This List Is Used

Nothing above blocks building the _real_ interface and logic for its feature — every gap has a documented interim solution per `DECISIONS.md`'s provider-abstraction pattern or the CMS-placeholder rule in `CLAUDE.md`. This list blocks only the **final, client-facing go-live** for the specific features it touches, tracked again in `DEPLOYMENT.md`'s go-live checklist.
