# Product media implementation

## Architecture

The catalogue originally stored 177 strings on 63 products, including 14 external Shopify assets. Product images now reference MediaAsset records; MongoDB contains metadata only. MinIO holds bytes. The existing private document/photo system is separate and unchanged.

`Product.media` is an ordered array of `{assetId, alt: {en, fr, ar}}`. Its first member is the sole primary image. `mediaRevision` provides compare-and-swap protection against competing gallery edits. `images` remains a deprecated materialized compatibility projection of stable API URLs for older cart, wishlist, order and recommendation consumers. Gallery saves update both fields together. New catalogue DTOs resolve assets in one batch and return `media` and `primaryImage` with thumbnail/card/main URLs and dimensions. No signed URLs are persisted.

## Storage and validation

The NestJS product-media endpoint accepts one file per request; the editor uploads a multi-selection independently so successful files survive another file's failure. JPEG, PNG and WebP are limited to 10 MiB, 40 megapixels, a minimum 32 pixels per side and one frame. Sharp checks the decoded format against MIME and extension, rejects corrupt data, rotates correctly and preserves alpha. Main images fit within 2000 pixels; cards within 800; thumbnails within 160. WebP quality is 92 (90 for thumbnails), without upscaling. Originals are retained.

Object keys are `products/{productId}/{assetId}/{original.ext,main.webp,card.webp,thumbnail.webp}`. Public API URLs are `/api/media/products/{assetId}/{main|card|thumbnail}` with immutable one-year caching. The API accesses the configured public MinIO bucket; it never signs short-lived catalogue URLs. Immutable asset IDs prevent stale bytes when replacing an image. Private AI photos and professional documents do not use this endpoint.

Uploads are idempotent per owning product and checksum. Failed uploads compensate already-written objects. Gallery saves reject unknown/unrelated assets and duplicate references. Duplication creates a draft sharing the immutable gallery, without copying stock/SKUs. Removing an image detaches only that product reference. Objects are deliberately retained for duplicate products and historical references; automatic garbage collection is not enabled. This is a retention policy, not a blanket storage deletion operation.

## Administration

The dedicated product list shows real thumbnails, names/SKUs, populated ranges/categories, visibility/status, AED prices and available stock. Product detail presents gallery, business sections, pricing/stock, translations, SEO and technical information separately. Create/edit share a component with pre-save previews, progress, independent errors/retry, localized alt text, replace/remove, drag ordering and keyboard move controls. Prices and inventory use the existing audited variant workflow.

Drafts can retain incomplete localized content. Publishing checks required EN/FR/AR content and a configured positive AED price for the relevant channel; UAE availability cannot be pending. Image/category checklist items are recommendations, not invented publishing blockers. Clinical descriptions and prices are never generated by the editor.

The root pathname transition bypasses admin, preserving its nested header/sidebar. Only main content animates for 180 ms with a 5-pixel entrance; reduced motion disables it. Same-resource filter queries retain previous rows. Product queries refresh every minute and editor saves invalidate active queries. Existing generic variant saves invalidate storefront queries too.

## Migration and recovery

Run `pnpm --filter @ioma/api exec ts-node src/scripts/migrate-product-media.ts` for backup/audit, or add `--apply` to migrate. It writes Extended JSON product/media backup and an incremental report beneath `scratch/product-media-{timestamp}` before changes. Local paths must remain inside the web public directory. Remote sources are HTTPS on explicitly approved official hosts, with bounded downloads, redirects and timeouts. Actual file signatures correct historical incorrectly named `.jpg` mirrors. If any image fails, the whole product's original gallery stays intact; the next run reuses successful asset uploads.

Local run: 63 products and 177 images migrated, including all 14 external images; no failures. Product count stayed 63. Repeated apply skipped 63 products, migrated zero, and kept 177 assets. Original backup: `scratch/product-media-2026-09-06T21-23-17-957Z/backup.ejson`; report alongside it. Do not remove backups or original files until production backup/recovery policies are established. The importer preserves managed image projections on existing products.

## Selection and consolidated management

Products supports page-scoped checkbox selection, mixed select-all state, clear selection, localized confirmation, pending/error states and bulk deletion. Filters/page changes clear selection. POST /api/admin/products/bulk-delete validates 1–100 IDs and commerce.manage before updating products to archived with deletedAt; list/search/reference lookups exclude deleted products and edits cannot republish them. Stored variants, media and historical references are retained.

Orders provides equivalent selection via POST /api/admin/orders/bulk-delete. This sets adminDeletedAt and hides records from the management list/search. Payment/fulfillment, customer history, accounting metrics and stock remain intact. The confirmation explicitly explains this operation is not cancellation or refund. Both operations are audited and idempotent.

Product Management now contains Catalogue, Inventory, Stock movements and Skin concerns tabs. Standalone navigation entries are removed; old list URLs redirect into the matching tab while preserving filters. Detail/edit links remain compatible. Categories and ranges support active/inactive status; public directory responses exclude inactive records. Product SEO is applied by server-generated PDP metadata.
